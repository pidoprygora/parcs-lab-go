# Набір експериментів для самостійного прогону

Цей документ містить готові сценарії, які можна запускати без зміни коду.
Сценарії читаються з JSON-файлу `scripts/experiments.json`.

## Швидкий старт

1. Підніми інфраструктуру за інструкцією з `docs/infrastructure.md` (Swarm, `parcs`, `docker-proxy`).
2. Налаштуй доступ контейнера до Docker API (через `docker-proxy`, як в `docs/usage.md`).
3. Запусти:

```bash
LEADER_URL=tcp://docker-proxy:4321 SKIP_PUSH=1 ./scripts/experiments.sh
```

Це виконає всі експерименти з `scripts/experiments.json` по черзі.
Наприкінці скрипт виведе підсумкову таблицю з:
- назвою експерименту,
- кількістю воркерів,
- часом виконання алгоритму (`ALGO_DURATION_MS`),
- статусом,
- розв'язком (`SOLUTION_JSON`).

## Запуск конкретного експерименту

```bash
LEADER_URL=tcp://docker-proxy:4321 \
EXPERIMENT=case4x4 \
SKIP_PUSH=1 \
./scripts/experiments.sh
```

`NUM_WORKERS` у цьому режимі використовується як глобальний дефолт.
Якщо у JSON для конкретного кейсу задано `num_workers`, він має пріоритет.

Доступні імена:
- `case3x3_base`
- `case3x3_diag_dominant`
- `case4x4`
- `case5x5_sparse`
- `all`

## Варіанти експериментів

### 1) Базовий контрольний (3x3)

- `EXPERIMENT=case3x3_base`
- Матриця: `[[2,1,-1,8],[-3,-1,2,-11],[-2,1,2,-3]]`
- Мета: перевірка коректності реалізації на відомому прикладі.
- Очікувано: `x=[2,3,-1]`.

### 2) Діагонально домінантна система (3x3)

- `EXPERIMENT=case3x3_diag_dominant`
- Матриця: `[[10,2,1,7],[2,10,3,8],[1,3,10,9]]`
- Мета: стабільна система з хорошою чисельною поведінкою.
- Що дивитися: відсутність помилок pivot та адекватний час виконання.

### 3) Середній розмір (4x4)

- `EXPERIMENT=case4x4`
- Матриця: `[[1,2,3,4,10],[2,1,1,0,4],[3,1,2,1,7],[1,0,1,2,5]]`
- Мета: перевірити, як працює розбиття рядків по worker-ах.
- Рекомендація: прогнати з `NUM_WORKERS=1`, `2`, `4` і порівняти логи.

### 4) Рідка 5x5 система

- `EXPERIMENT=case5x5_sparse`
- Матриця: `[[10,0,2,0,1,7],[0,9,0,1,0,8],[2,0,8,0,1,6],[0,1,0,7,2,5],[1,0,1,2,6,9]]`
- Мета: перевірити обробку більших систем і обнулення near-zero значень.
- Рекомендація: спробувати `NUM_WORKERS=2` та `NUM_WORKERS=5`.

## Формат JSON для пакетного запуску

Файл може бути:
- або об'єктом з ключем `experiments`,
- або масивом експериментів.

Приклад:

```json
{
  "experiments": [
    {
      "name": "case3x3_base",
      "num_workers": 2,
      "matrix": [[2, 1, -1, 8], [-3, -1, 2, -11], [-2, 1, 2, -3]]
    },
    {
      "name": "case4x4",
      "num_workers": 4,
      "matrix": [[1, 2, 3, 4, 10], [2, 1, 1, 0, 4], [3, 1, 2, 1, 7], [1, 0, 1, 2, 5]]
    }
  ]
}
```

Запуск з кастомним JSON:

```bash
LEADER_URL=tcp://docker-proxy:4321 \
INPUT_JSON=./my-experiments.json \
SKIP_PUSH=1 \
./scripts/experiments.sh
```

## Експерименти на масштабування

Для кожного fixed кейсу (наприклад `case5x5_sparse`) прогони серію:

```bash
for w in 1 2 3 4 5; do
  echo "=== NUM_WORKERS=$w ==="
  LEADER_URL=tcp://docker-proxy:4321 \
  EXPERIMENT=case5x5_sparse \
  NUM_WORKERS=$w \
  SKIP_PUSH=1 \
  ./scripts/experiments.sh
done
```

Що аналізувати:
- `ALGO_DURATION_MS` у фінальній таблиці,
- кількість підключень `Connection to ... established` у логах,
- чи змінюється точність результату.

## Експеримент на стійкість (помилка)

Спробуй матрицю з лінійно залежними рядками:

```bash
LEADER_URL=tcp://docker-proxy:4321 \
NUM_WORKERS=2 \
MATRIX='[[1,2,3,4],[2,4,6,8],[3,6,9,12]]' \
SERVICE_NAME=gauss-singular-test \
SKIP_PUSH=1 \
./scripts/run.sh
```

Очікувано: помилка типу `singular or near-singular matrix`.

## Мінімальний шаблон для звіту

Для кожного запуску зафіксуй:
- назву експерименту,
- `NUM_WORKERS`,
- матрицю,
- отриманий вектор `x`,
- підсумок (успішно / помилка),
- короткий коментар по часу виконання.
